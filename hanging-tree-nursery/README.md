# 📖 Read This First — How To Update This Website

This file explains how to make changes to this website yourself — no
coding, no software to install, just your web browser. Even if you've
never used GitHub before, everything below will make sense.

**The site updates itself automatically within a minute or two after you
save a change.** There's nothing else to click, publish, or deploy.

## Before you start

You'll need a free GitHub account, and someone at ZigTech (Gerald) will
need to add you as a collaborator on this repository so you can make
changes. If you don't have a GitHub login yet, go to
[github.com/join](https://github.com/join) and create one, then send your
username to Gerald so he can grant access.

## Where things live in this repository

All swappable documents are in the `pdfs` folder, split into three
subfolders:

- **`pdfs/availability`** — the five current stock/availability sheets
  (Bloomers, Ferns/Orchids/Bromeliads, and the three pot size categories).
  Filenames start with `availability_`.
- **`pdfs/price-lists`** — the five price list PDFs, one per category,
  matching the same five categories as availability. Filenames start with
  `price_list_`.
- **`pdfs/forms`** — the credit application and new customer information
  form. These change rarely.

## Editing text on a page

1. Open the page file you want to change (for example, `contact.html`) in
   this repository on GitHub.
2. Click the pencil icon in the top right of the file view.
3. Find the text you want to change and edit it directly. The surrounding
   code (anything inside `< >` brackets) should stay exactly as it is —
   only change the words between the tags.
4. Scroll down to "Commit changes." Leave "Commit directly to the main
   branch" selected, add a short note about what you changed, and click
   the green "Commit changes" button.
5. Give it a minute or two, then check the live site.

If you're not sure whether an edit is safe to make this way, or the change
involves more than swapping out a sentence, reach out to Gerald first
rather than guessing.

## Replacing a document (the everyday task)

1. Go to the appropriate subfolder above — for example:
   `https://github.com/geraldz-zigtech-llc/website/tree/main/hanging-tree-nursery/pdfs/availability`
2. Click on the file you want to replace (for example,
   `availability_blooming.pdf`) to open it.
3. Click the pencil/edit icon in the top right, **or** just drag your new
   file onto the file listing in the folder — GitHub will offer to
   replace the existing file.
4. **Important: keep the exact same filename.** The web pages link to
   these files by name, so uploading a replacement with the same name
   keeps every link on the site working automatically. A different
   filename will break the existing link until someone updates the page
   to point at the new filename.
5. Scroll down to "Commit changes." Leave "Commit directly to the main
   branch" selected, add a short note (e.g. "Update bloomers availability
   8/28"), and click the green "Commit changes" button.
6. Give it a minute or two, then check the live site — your new PDF will
   be what visitors see when they click that link.

## Adding something brand new (not just replacing a file)

If you're adding a document that doesn't already exist on the site (a new
category, for instance), you'll need two things:

1. **Upload the file** to the appropriate subfolder the same way as
   above, using "Add file" → "Upload files" instead of replacing an
   existing one.
2. **Add a link to it on the page** — this part needs a small code edit,
   so reach out to Gerald for that step. Once the link exists, updating
   that same file going forward is just the "Replacing a document" steps
   above — no help needed after that.
